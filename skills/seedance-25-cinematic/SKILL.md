# Seedance 2.5 Cinematic Director

영화 같은 프롬프트를 사건 → 관찰 가능한 반응 → 인물과 카메라의 변화 → 마지막 상태로 설계한다. 사용자가 제공한 2.0 가이드의 소재 역할, 물리적인 연기, 타임라인, 카메라·음향 작법을 2.5 디렉터 브리프로 적용한다.

## 적용 범위와 자료

- 전체 프롬프트 작성·수리에는 [2.5 프롬프트 작성법](../seedance-2-5-prompting/references/seedance-25-writing-rules.md)을 적용한다. 사건·참조 역할·렌즈와 무빙·긍정문 우선·소리 이름 검사·숫자 점검을 기존 구조 안에 통합하며 첫 실패부터 결과에 맞춰 수정한다.
- 버전·분량·수정·출력의 기준은 [기본 2.5 스킬](../seedance-2-5-prompting/SKILL.md)이다. 이 문서는 영화 연출을 보충하며 모델 사양을 따로 정의하지 않는다. 현재/버전 미지정 씨댄스는 기본 스킬의 라우팅을 따른다. 명시적인 일반 2.0 요청은 기존 2.0 스킬로 보낸다.
- 스토리만·이미지만·둘 다 제공된 새 장면은 [입력에서 장면으로](../seedance-2-5-prompting/references/story-image-scene-brief.md)를 먼저 읽는다. 스토리의 사건·감정과 실제 이미지의 시각 정보를 이해한 뒤 어울리는 장면을 만들고, 그 장면에 맞는 카메라를 골라 전체 프롬프트로 작성한다.
- 2.0 자료의 변환, 전체 영화 프롬프트 작성, 원샷·연장에는 [영화 연출 변환 가이드](references/film-direction-migration.md)를 읽는다. 5블록 대응표, 역할 배정, 30초 원테이크 예시가 있다.
- 장면에 맞는 카메라 모션·구도·블로킹·전환을 고를 때는 [아이캔디 연출 연결](../seedance-2-5-prompting/references/eyecandy-camera-direction.md)을 읽는다. 감정·인물 동작·공간·가독성을 기준으로 기법과 일반 촬영을 비교하고, 선택한 결과를 2.5 카메라 문장으로 작성한다. 고정 숏과 이미 정한 경로도 유효한 선택이다.
- 액션·추격·메카·충격·등장 장면이나 해당 장면의 원샷에는 [GODSTOUCH 액션 카메라](../seedance-2-5-prompting/references/godstouch-action-camera.md)를 추가로 읽는다. 장면에 맞는 카메라 후보, 사건에 반응하는 이동, 접촉과 결과의 타이밍을 보강하고 숨은 컷을 실제 원샷과 구분한다.
- 이동 카메라는 [카메라 컴파일러](../seedance-2-5-prompting/references/camera-motion.md)를 사용한다.
- BGM 금지·원치 않는 음악·완전 무음·첨부 오디오만·무반주 노래에는 [NO-BGM 가이드](../seedance-2-5-prompting/references/no-bgm.md)를 읽는다.
- 기능·업로드·길이·출력 설정 질문은 기본 스킬의 모델·출처 참고자료와 현재 UI로 확인한다.

## 2.5에 맞춘 핵심 규칙

1. **요청 길이 보존.** 30초 요청이고 선택한 UI가 지원하면 하나의 0–30초 프롬프트로 쓴다. 2.0식 15초+15초 연장을 자동 적용하지 않는다. 사용자가 요청한 더 짧은 길이도 유지한다.
2. **역할 계층.** 실제 제공된 태그를 대소문자·공백까지 그대로 사용한다. 각 소재의 주 역할, 유지 속성, 허용 변경, 충돌 시 우선순위를 쓴다. 참조가 없으면 텍스트로 작성한다.
3. **주체와 카메라 분리.** 인물의 행동과 카메라의 이동·회전·렌즈·초점을 별도 절로 쓴다. 한 비트에 핵심 행동 하나와 주 카메라 이동 하나를 둔다.
4. **행동에 맞는 비트.** 6–8초 내러티브 비트와 마지막 3–4초 여운은 작성 기본값이다. 대사·액션·동기화에 맞춰 조정하며 매 3초 분할을 강제하지 않는다. 원본 오디오 립싱크는 소스의 발화·쉼·호흡이 시간을 정한다.
5. **컷 정책과 마지막 상태.** 원테이크는 비트 사이의 구도·위치·속도·초점이 이어지게 설계한다. 편집 영상은 허용 컷 시점과 다음 시작 구도를 명시한다. 마지막 자세·시선·소품·빛·카메라 상태를 정한다.
6. **작성 예산.** 기본 스킬의 5,000자 상한, 정확한 문자 수 측정, 초과 시 언어 전환과 수정 시 전체 재작성 규칙을 따른다. 분량은 로컬 작성 규칙이며 짧게 완성되면 늘리지 않는다.

## 영화 연출 작법

- **감정의 증거를 쓴다.** “불안하다”를 “문손잡이 위 손가락이 멈추고 들이마신 숨을 잠시 붙잡는다”로 풀어 쓴다. 감정어는 목적을 설명할 수 있지만 연기 지시를 대신하지 않는다. 한 반응은 신체 부위·행동·횟수/속도를 갖춘 두세 단서를 기본으로 하고, 핵심 행동까지 그 수에 맞춰 삭제하지 않는다.
- **카메라 이동에 이유를 둔다.** 알아차림에는 얼굴로 접근, 거리감에는 후퇴, 인물이 발견한 대상에는 시선에 따른 재구도를 쓴다. 정지와 같은 샷 크기의 유지도 의도적인 선택이다.
- **표정 과장보다 변화의 순서.** 시선 이동 → 호흡 변화 → 손이나 몸의 행동처럼 핵심 반응에 필요한 순서만 남긴다. 모든 비트에 눈물·떨림을 반복하지 않는다.
- **접촉은 원인부터 결과로.** 시작 이미지의 접촉 상태를 보존하고 필요한 잡기 → 힘의 방향 → 물체 이동 → 끝 접촉 상태를 쓴다. 이미 손잡이를 쥐었다면 다시 손을 뻗게 하지 않는다.
- **일관성은 속성별로.** 얼굴·헤어·의상·체형 등 실제 참조의 핵심 특징을 지정한다. 여러 각도의 자료는 도움이 될 때 사용하며 필수 업로드나 완벽한 재현을 약속하지 않는다. 동작·카메라 영상에서 외모가 섞이지 않도록 역할을 나눈다.
- **조명과 재질을 연결한다.** 광원 위치·방향·색과 그것이 얼굴, 유리, 젖은 바닥, 천에 만드는 변화를 쓴다. 필름 그레인·색조·심도는 장면을 지지하는 소수의 선택만 사용한다.
- **음향도 연출이다.** 무음, 현장음, 음악, 소스 오디오 중 요청에 맞는 모드를 고른다. 영화 같다는 이유만으로 BGM을 추가하거나 삭제하지 않는다.

## 카메라·렌즈 어휘

| 용어 | 물리적 의미 | 연출 적용 |
| --- | --- | --- |
| push in / dolly in | 카메라 본체가 접근 | 미디엄에서 얼굴로, 깨달음에 접근 |
| pull back / dolly out | 카메라 본체가 후퇴 | 관계·공간·여운을 드러냄 |
| pan / tilt | 위치를 유지한 수평/수직 회전 | 시선 또는 위아래 대상 연결 |
| truck / side tracking | 옆으로 이동 / 인물 옆을 따라감 | 배경 패럴랙스와 이동 관계 유지 |
| follow / lead tracking | 인물 뒤 / 앞에서 동행 | 진입·보행·추적 |
| arc / orbit | 인물 주변의 곡선 경로 | 인물 회전과 구별, 출발·도착 각도 지정 |
| crane / boom | 높이 또는 대각선 공간 이동 | 공간 공개, 높이 변화와 조준을 분리 |
| dolly zoom | 본체 이동과 반대 방향 광학 줌 | 인물 크기 유지 의도와 배경 변화 명시 |
| whip pan | 안정 구도 → 빠른 회전 블러 → 안정 구도 | 같은 공간의 연결 또는 명시한 편집 지점 |
| rack focus | 초점 대상 변경 | 카메라 이동과 분리해 근경·원경 순서 지정 |
| locked-off | 위치·조준·초점거리 고정 | 정지 프레임 안에서 인물 행동 관찰 |
| one take / one shot | 편집 없는 연속 촬영 | 이동명이 아니라 컷 정책 |
| fisheye | 강한 광각 왜곡의 렌즈 표현 | 이동명이 아니라 주관적 시각 표현 |

샷 크기는 ECU(눈·입 등 세부), CU(얼굴), MCU(머리·어깨), MS(허리 위), FS(전신), WS(환경)에서 목적에 맞춰 선택한다. 렌즈·프레임레이트·화면비 숫자는 UI 설정이 아니면 시각적 의도이며 확정 출력값처럼 쓰지 않는다.

## 디렉터 브리프 구조

```text
설정: 모드 / 요청 길이 / 화면비·출력 의도 / 원테이크 또는 허용 컷
소재: 실제 태그 / 역할 / 유지 속성 / 허용 변경 / 역할별 우선순위
장면: 인물 / 목적 / 공간 관계 / 광원 / 연속성 제약
비트: 시간 → 주체 행동·관찰 가능한 반응 → 별도 카메라 절 → 끝 상태
카메라: 목적 → 시작 구도 → 주 이동 → 경로·속도 → 블로킹 → 렌즈·초점 → 끝 구도·컷
음향: 선택 모드 → 허용 소리·출처 → 동기화 → 요청된 제외
마지막 프레임: 자세·시선·소품 / 카메라 위치·방향·초점 / 빛·소리의 상태
```

NO-BGM이 중요한 장면은 설정부에 먼저 선언하고 음향부 끝에서 짧게 재확인한다. 본문은 사용자 언어로 쓰되 실제 태그와 `NO BGM` 식별자는 보존한다.

## 수정·검증·출력

수정 요청은 기본 스킬의 active brief 규칙으로 처리한다. 폐기된 카메라·음악·대사와 관련 타이밍을 제거하고, 영향을 받는 시작/경로/끝을 다시 설계한 완전한 프롬프트 하나를 반환한다.

- 실제 태그만 있고 각 역할과 충돌 우선순위가 분명한가?
- 타임라인이 요청 길이를 공백·중복 없이 덮는가? 소스 립싱크의 내부 시간을 임의로 바꾸지 않았는가?
- 감정 변화가 관찰 가능한 행동으로 드러나는가?
- 카메라 경로가 연결되고 컷 정책과 충돌하지 않는가?
- NO-BGM과 무음·소스 전용·무반주 보컬을 혼동하지 않았는가?
- 마지막 상태가 읽히고, 문자 수와 초과 처리 규칙을 충족하는가?

반환 순서: 필요한 설정 한 줄 → 복사용 전체 프롬프트 코드 블록 → `프롬프트 길이: N/5000자` → 참조가 있으면 역할 맵 → 2–4줄 카메라 근거 → 수리일 때만 좁은 재시도 지시. 영상 생성 요청 없이 생성 도구를 호출하지 않는다.
