# 씨댄스 2.5 프롬프트 작성법 — 5팁 적용

사용자가 제공한 `교안_마르셀의심장_두번째후기_프롬프트5팁.zip` 안의 동명 HTML 교안과 발췌 이미지를 2.5 작성 규칙으로 통합했다. 교안은 제작팀의 채택 사례에서 얻은 관찰이며, 모델의 공식 사양이나 성공 보장이 아니다. 최신 사용자 지시와 기본 스킬의 버전·분량·참조·수정 규칙을 우선한다. 특정 작품의 인물·소품·음향을 다른 장면의 기본값으로 가져오지 않는다.

## 장면에 필요한 지시를 먼저 고른다

작성 전 실제 입력을 읽고 장면의 핵심 목적을 내부적으로 한 문장으로 정한다. 수정이면 최신 지시를 반영한 active brief부터 만든다. 참고자료를 읽었다고 모든 기법·항목을 출력에 넣지 않는다.

1. **보존할 조건.** 사용자가 명시한 길이·언어·컷·태그·참조 역할·동작·카메라·음향·결말은 유지한다. 복잡한 아크, 랙 포커스, 조명 변화도 요청했다면 생략하지 않는다.
2. **목적을 실현하는 지시.** 필수 행동의 원인과 결과, 감정이 보이는 반응, 필요한 구도와 공간 관계, 허용 음향, 중요한 연속성만 구체화한다. 빈칸을 채우려고 손의 좌우·각도·장식·미세 표정을 늘리지 않는다. 명시한 렌즈 수치는 보존하고 선택한 렌즈/주 이동은 카메라 절 앞에 쓴다.
3. **제거해도 되는 문장.** “이 문장을 빼면 핵심 행동·감정·구도·허용 음향·중요한 연속성이 실제로 달라지는가?”를 묻는다. 사용자 지정도 아니고 목적에 실질적인 차이도 없으면 중복 고정문, 장식 수식어, 무관한 기법과 금지 목록을 뺀다.

| 장면의 중심 | 우선 남길 지시 | 조건이 있을 때 추가 |
| --- | --- | --- |
| 조용한 감정·망설임 | 결정이 보이는 손·시선 등 최소 반응, 반응이 읽히는 구도와 끝 상태 | 감정 변화를 돕는 이동·초점·빛 |
| 추격·접촉·문 통과 | 인물 순서와 동선, 접촉·힘·결과, 통과 여유, 연결된 카메라 경로 | 사건에 맞는 GODSTOUCH 후보, 요청한 충격·속도 변화 |
| 뮤직비디오·퍼포먼스 | 요청한 퍼포먼스, 참조 정체성, 음악/소스 역할과 필요한 동기화 | 요청한 컷·전환·안무; NO BGM은 해당 음향 요청일 때 |
| 제품·브랜드 | 제품 형상과 읽혀야 하는 정보, 행동, 이를 보여주는 구도·빛 | 의미 있는 반사·질감·이동 |

표는 선택의 출발점이다. 여러 목적이 필요하면 함께 사용하며 기법 개수로 제한하지 않는다. 같은 원샷에서 변하지 않는 카메라·참조·연속성 조건은 한 번 쓰고 각 비트에는 달라지는 행동과 상태를 쓴다. 고정 숏에 이동 경로·이동 속도를 억지로 채우지 않는다. 설정·실제 참조 역할·주체 행동·카메라·음향·마지막 상태는 간결하게 모두 갖춘다.

첫 작성은 필요한 긍정문과 간결한 제약으로 시작한다. 실제 실패가 보고되면 그 실패 층에 필요한 제약만 보강한다. 예를 들어 원치 않는 줌이 생기면 카메라의 초점거리·구도 고정을 강화하되, 정상인 연기·조명·음향까지 다시 설계하지 않는다. 최신 지시와 의존 관계를 반영한 전체 프롬프트를 반환하며 생성 재시도는 실제 제작 권한을 따른다. 이 선택표나 내부 점검 과정을 최종 프롬프트 앞에 출력하지 않는다.

## 1. 사건과 형식을 먼저, 참조는 역할별로

- **한 줄 사건 → 형식 → 참조 역할 → 시간별 본문 → 마지막 물리 상태** 순서로 설계한다. 기존 디렉터 브리프의 블록 안에 이 순서를 적용하며 별도 중복 템플릿을 붙이지 않는다. 길이·컷 정책·음향 정책을 정한 뒤 본문에서 바꾸지 않는다.
- 관객이 받아야 할 중심 사건을 먼저 정한다. 사건 밀도가 높으면 장식·동시 행동부터 덜어낸다. 교안의 ‘요청 두 개’는 집중도를 점검하는 기준이지 필수 사건의 상한이 아니다. 요청한 원샷을 임의 분할하거나 길이·결말을 바꾸지 않는다.
- 참조마다 **주 역할 / 그 역할에 한정한 유지 속성 / 상속하지 않을 속성 / 장면에서 정할 표정·행동**을 짧게 쓴다. 실제 태그를 그대로 사용하고 명시된 보조 역할은 유지한다. 얼굴 시트의 웃음을 슬픈 장면에 고정하거나 동작 영상의 의상·배경·음향까지 복사하지 않는다. 모든 참조를 무조건 네 줄로 늘릴 필요는 없다.
- 대사 원문은 해당 비트 한 곳에만 쓴다. 다른 블록에서는 발화 시작·종료 큐를 참조한다. 컷은 대사가 끝난 뒤 짧은 반응 여유를 두되, 사용자가 지정한 대사 겹침·편집·소스 타이밍을 우선한다. 입을 일부 가리는 구도는 장면에 맞는 선택일 때만 쓰고, 정확한 립싱크 요청을 자동으로 가리지 않는다.

## 2. 카메라 문장은 렌즈와 고정/주 이동부터

내부에서는 목적·시작·경로·끝을 먼저 설계하고, 최종 CAMERA 절은 **선택한 mm → LOCKED OFF 또는 주 이동 하나 → 높이·구도·경로·속도 → 초점·끝 상태**로 읽히게 쓴다. mm는 시각적 의도이며 실제 렌즈 제어를 보장하지 않는다. 인물 CU에는 망원, 공간 소개에는 광각을 출발점으로 삼되 이미지의 원근, 실제 공간, 얼굴 왜곡, 사용자 선택에 맞춰 바꾼다.

한 컷은 고정 또는 주 이동 하나를 기본으로 한다. 여러 비트가 있다는 이유로 새로운 이동을 계속 추가하지 않는다. 명시적으로 필요한 복합 동작·단계적 경로는 주 이동과 종속 조준·초점을 구분하고, 앞 끝 상태에서 다음 시작 상태가 이어지게 설계한다. 모든 복합 이동이 실패한다고 단정하지 않는다.

같은 연속 컷에서는 초점거리를 유지하고, 렌즈 교체는 허용된 컷 경계에서 한다. 요청된 광학 줌·돌리 줌은 별도 의도적 예외이며 고정 숏으로 부르지 않는다. 샷 크기 변경은 실제 이동이나 허용된 컷으로 해결할 수 있지만, 원샷에 렌즈 교체·하드컷을 몰래 넣지 않는다. 컷이 바뀌면 렌즈·고정/이동·끝 구도가 읽히게 쓰고, 인물의 화면 좌우는 구도·시선·동선·축 연속성에 중요하거나 사용자가 지정했을 때 명시한다. 같은 원샷의 변하지 않는 조건은 반복하지 않는다.

전경을 쓰는 연출은 **접근해서 덮기 / 지나가며 드러내기 / 후퇴해서 열기** 중 장면 목적에 맞게 고른다. 가리는 물체, 드러날 대상, 시작·끝 위치를 정하고 인물 관계의 180도 축과 화면 좌우를 유지한다. 축 변경이 요청되면 중립 구도나 연속 이동으로 변화가 읽히게 한다. 가림이 곧 편집 허가는 아니다. 실제 원샷과 숨은 컷은 [GODSTOUCH](godstouch-action-camera.md)의 구분을 따른다.

## 3. 원하는 상태 먼저, 필요한 금지는 종류별로

긍정문으로 원하는 구도·행동·허용 소리를 먼저 확정한다. 부정문은 카메라 고정과 NO-BGM 등 바꿀 수 없는 조건의 보강에 사용한다. 명시된 정체성·인원·소품 보호에 필요한 제외도 허용하되, 무관한 금지 목록을 모든 장면에 붙이지 않는다.

고정 숏은 안정된 위치·조준·초점거리와 유지할 구도를 먼저 간결하게 쓴다. 사용자가 상세한 금지를 요구하거나 실제로 원치 않는 움직임이 나온 수리에서만 관련 대체 이동을 CAMERA 절 뒤에 한 번 구체화한다. 다음은 여러 이동을 막아야 하는 경우의 확장 예시이며, 모든 고정 숏에 통째로 붙이는 기본문이 아니다:

```text
CAMERA: 85mm, LOCKED OFF close-up. Fixed camera position, orientation, focal length and framing; the actor moves within the frame. No camera translation, pan, tilt, roll, whip-pan, dolly/push-in/pull-back, truck/track, pedestal/crane, orbit/arc, drift/reframe, optical or digital zoom, handheld shake, or gimbal float.
```

이 문장은 고정 요청용이다. 움직이는 숏에서는 선택한 이동을 금지하지 않는다. **초점 이동, 재생 속도, 편집은 카메라 이동과 별개**다. 고정 숏에서도 요청된 rack focus는 유지한다. speed ramp·slow motion·freeze frame·dissolve·fade는 해당 시간·편집 정책이 금지할 때만 제외한다. 정속 재생이나 원컷 조건이 없는데 예시 전체를 복사해 금지하지 않는다.

핵심 고정·NO-BGM 조건은 해당 카메라·음향 블록에서 적용 범위가 분명하게 한 번 쓴다. 특히 중요한 조건은 설정부에도 짧게 표시할 수 있다. 실제 수리에서 추가 보강이 필요할 때만 마지막 제외 절에 요약하고, 긴 목록을 여러 곳에 반복하지 않는다. 현재 필요한 금지와 폐기된 지시를 기억시키는 ‘이전 무빙 말고’ 문장을 구분한다.

## 4. 소리·연기는 관찰 가능한 사건으로

[NO-BGM 가이드](no-bgm.md)의 **허용 소리 목록과 본문·부정문의 소리 이름 검사**를 적용한다. 불필요한 구체적 음원 이름을 지우는 것은 혼선을 줄이는 작성 요령이다. 이름이 있으면 반드시 소리가 생성된다거나 부정문이 무력해진다는 모델 원리로 설명하지 않는다. 허용된 현장음·대사·노래, 정확한 참조 태그, 화면에 필요한 무음 소품은 보존한다. 허용된 화면 밖 소리는 소리의 출처·방향·거리·시간에 따른 변화를 필요한 만큼 적는다.

감정어 뒤에 표정·호흡·손처럼 **신체 부위 + 관찰 가능한 행동 + 횟수/속도**를 붙인다. 한 번의 손 멈춤만으로 결정이 읽히면 그것으로 충분하다. 반응이 더 필요할 때 두세 단서로 확장하되 개수를 채우려고 턱 조임·눈 깜빡임을 덧붙이지 않는다. 간결함을 이유로 필수 사건을 삭제하지 않는다.

접촉은 실제 인과 순서로 쓴다: 필요한 접근 → 접촉/잡기 → 힘의 방향 → 물체의 움직임 → 끝 접촉 상태. 이미 손잡이를 쥔 시작 이미지라면 다시 손을 뻗지 않는다. 당기는 문인지 미는 문인지, 손·문짝·몸·카메라가 움직일 공간을 확인한다.

```text
시작부터 오른손이 문손잡이를 쥐고 있다. 눈이 한 번 크게 뜨이고 어깨가 잠시 멈춘다. 접촉을 유지하며 손잡이를 몸 쪽으로 당긴다. 문짝이 열릴 공간만큼 몸을 뒤로 옮긴 뒤, 열린 문과 손의 접촉을 유지한다.
```

## 5. 숫자·시간·재시도 점검

- 인원수·소품 크기·나이·렌즈처럼 정체성과 연속성에 필요한 **제공된 값**은 유지한다. 진행량은 불필요한 각도 수치 대신 ‘문이 다 열리고 통로가 보임’처럼 읽히는 결과로 쓸 수 있다. 정밀 수치가 명시된 요청은 임의로 없애지 않는다. 이미지와 텍스트가 다르면 자동으로 텍스트 승리를 선언하지 말고 최신 지시와 참조 역할의 우선순위를 적용한다.
- TITLE·FORMAT·GLOBAL·비트·END STATE의 길이와 상태가 일치하는지 대조한다. fps가 주어졌을 때의 `초 × fps`는 작성자의 산수 검산이며 모델의 프레임 준수 증거가 아니다. 빠른 실제 동작을 슬로모션으로 보여줄 때는 사건 자체의 움직임과 재생 속도를 다른 절로 적고, 재생 결과가 요청 길이에 들어가게 한다.
- 첫 실패부터 [결과 기반 수정·재시도](revision-workflow.md#first-failure-repair-loop)를 적용한다. 수정 지점은 좁게, 반환은 현재 지시를 반영한 전체 프롬프트로 한다. 제출 승인본이 있으면 실제 제출문과 대조하고, 바뀐 문장을 승인받은 원문인 것처럼 보내지 않는다.
- 교안의 크레딧 가격·40k 바이트·duration 타입·BOM 오류 사례는 그 제출 환경의 기록이다. 일반 2.5 사양이나 기본 스킬의 5,000자 상한을 대체하지 않는다. 실제 API 파일 제출 작업에서만 현재 스키마·인코딩·허용 바이트·BOM 요구를 확인한다. 프롬프트 작성만 요청받았으면 API 필드나 생성·결제·자동 재시도를 실행하지 않는다.
