# 장면에 맞는 아이캔디 연출 → 씨댄스 2.5 카메라 프롬프트

이 문서는 두 스킬을 함께 쓰기 위한 로컬 작성 규칙이다. 아이캔디는 장면에 맞는 시각 기법을 판단하는 데 쓰고, 최종 문장은 기본 2.5 스킬의 카메라 컴파일러와 출력 규칙으로 작성한다.

## 언제 참고하는가

2.5 프롬프트를 작성·수정하면서 카메라 모션, 구도, 인물 배치, 공간 공개, 장면 전환을 선택해야 할 때 사용한다. 사용자가 아이캔디라는 이름을 말하지 않아도 적용한다. 영화 같다는 요청만으로 화려한 기법을 넣거나 이미 정한 촬영 방식을 바꾸지 않는다.

오타·언어·음향만 수정하는 요청이고 카메라가 영향을 받지 않으면 기존 카메라를 보존한다. 사용자가 지정한 경로나 참조를 고치는 요청은 실패한 부분에 한해 적합성을 다시 검토한다.

## 입력 이해가 먼저

스토리나 이미지에서 새 장면을 만드는 요청은 [입력에서 장면으로](story-image-scene-brief.md)의 읽기·역할 배정·장면 구성을 먼저 수행한다. 그 결과로 정해진 행동·감정·공간에 카메라를 맞춘다. 카메라 기법을 먼저 고른 뒤 스토리나 이미지의 의미를 거기에 맞춰 바꾸지 않는다.

## 액션 장면 보강

격투·추격·메카·충격·등장 장면 또는 그 장면의 연속 원샷에서는 [GODSTOUCH 참고자료](godstouch-action-camera.md)를 함께 읽는다. 아이캔디로 장면 적합성을 판단한 뒤, 사건에 반응하는 카메라 동기와 접촉·반응 타이밍을 보강한다. 두 자료의 후보를 모두 쌓지 말고 한 가지 주 경로로 컴파일한다. GODSTOUCH의 용어를 EYECANDY 공식 카테고리로 취급하지 않으며, 비액션 장면과 영향을 받지 않는 카메라는 기존 선택을 유지한다.

## 선택과 변환

1. **장면이 보여줘야 할 변화부터 파악한다.** 인물의 목적과 감정 변화, 관찰 가능한 동작, 관객이 알아차릴 대상, 공간의 깊이·장애물, 사용 가능한 시간, 정체성·제품 가독성, 컷 정책을 정리한다. 카메라가 움직여 얻는 정보나 감정적 효과가 없으면 고정을 후보에 둔다.
2. [아이캔디 스킬](../../eyecandy-visual-development/SKILL.md)과 [의도별 후보표](../../eyecandy-visual-development/references/intent-routing.md)를 읽는다. 표는 후보를 찾는 자료다. 첫 번째로 실행 가능한 기법을 그대로 고르지 말고 장면에 적합한 후보와 평범한 촬영을 비교한다. 의도 분류에 억지로 맞출 필요가 없는 장면은 일반 영화 문법으로 설계한다.
3. 실제 검토할 후보의 technique 파일만 읽고 Required Inputs, Use When, Avoid When, Preservation Rules를 적용한다. 얼굴·로고·공간 관계·지정된 카메라를 훼손하거나 없는 참조·장애물을 요구하는 기법은 선택하지 않는다. 사용자나 참조가 이미 정한 카메라 경로는 기법 선택보다 우선한다.
4. **선택 이유는 그 장면의 구체적인 변화로 쓴다.** “시네마틱해서” 대신 “인물이 답하기 직전 멈춘 손에서 얼굴로 주의를 옮기기 위해”처럼 설명한다. 기법을 선택했다면 taxonomy의 실제 이름과 slug를 사용한다. 기본 팬·돌리·고정을 아이캔디 고유 기법으로 꾸며 부르지 않는다.
5. 선택을 [카메라 컴파일러](camera-motion.md)의 항목으로 변환한다:
   `장면 목적 → 시작 구도 → 주 이동 또는 정지 → 물리적 경로·방향 → 속도·감속 → 인물과 카메라의 관계 → 렌즈·초점 → 끝 구도 → 컷/연속성`.
   인물 동작과 카메라 본체 이동, 조준 회전, 렌즈·초점을 분리한다. “Arc 적용”으로 끝내지 않고 무엇을 중심으로 어디에서 어디까지 움직이며 무엇이 읽혀야 하는지 쓴다.
6. 한 비트에 주 카메라 이동 하나를 둔다. 아이캔디의 보조 기법은 별도 기능을 수행하고 경로·컷 정책과 양립할 때만 쓴다. 원테이크 안의 시간 비트는 독립된 숏이 아니므로 기법 다양성을 위해 이동을 바꾸지 않는다. 다음 비트는 직전 끝 상태에서 이어진다.

## 장면 적합성의 예

| 장면 요구 | 판단과 카메라 문장에 담을 것 |
| --- | --- |
| 고정 미디엄 클로즈업의 고백 | 고정을 유지한다. 표정과 시선이 읽히는 구도·초점·관찰 시간을 명시하며 긴장감만으로 돌리 줌을 추가하지 않는다. |
| 고급 시계, 로고 선명, 20초 원테이크 | 정지·완만한 접근·얕은 아크 중 로고 평면과 반사를 보존하는 구도를 고른다. 시작/끝 시점과 가독성 유지 구간을 쓰고 요청한 20초를 유지한다. |
| 인물이 문을 지나 새로운 공간을 발견 | 실제 열린 문과 통과 여유, 인물 시선, 공개될 대상을 확인한다. 가림이나 패럴랙스가 필요할 때만 해당 기법을 검토하고 벽 통과나 숨은 컷을 만들지 않는다. |
| 이미 정한 뒤따르기 숏에서 BGM만 삭제 | 경로·프레이밍·속도·초점을 유지하고 음향만 갱신한다. 새로운 연출 선택으로 기존 촬영을 덮지 않는다. |

예시는 고정 처방이 아니다. 장면에 맞는 기법이 없으면 정지나 단순한 이동을 선택한 이유를 쓰면 된다.

## 최종 출력에 넣는 방식

아이캔디의 Scene Intent → Selected Technique → Reason → Visual Motif → Camera/Blocking/Scale Rule → Storyboard Translation은 선택을 위한 내부 정리로 사용한다. 사용자가 별도 연출표·스토리보드를 요청한 경우에는 그 결과도 제공한다.

일반적인 2.5 프롬프트 요청에서는 별도 아이캔디 보고서나 두 번째 프롬프트를 붙이지 않는다. 선택 결과를 하나의 완전한 2.5 프롬프트에 녹이고, 기존 2–4줄 카메라 근거에 장면 적합성 및 선택 기법 또는 일반 촬영 이유를 짧게 설명한다.

실제 참조 태그, 요청 길이, NO-BGM/소스 오디오 모드, 5,000자 상한과 초과 처리, 최신 수정 지시는 기본 2.5 스킬이 관리한다. 원테이크·고정 카메라·정체성·제품 가독성은 연출 효과보다 우선한다.
