# GODSTOUCH: 장면에 맞는 액션·원샷 카메라

## 출처와 적용 범위

사용자가 제공한 CODEONESHOT의 `GODSTOUCH_CAMERA_BIBLE.pdf`(15쪽)를 씨댄스 2.5 작성 방식으로 각색했다. 장면별 후보는 원문 8–10쪽, 조합·제외 사항은 11쪽, 액션 타이밍은 12쪽, 동작에 반응하는 카메라는 2–6쪽과 13–14쪽을 참고했다. 작품별 스타일 해석, 수치, lock 표기는 저자의 작성 관례이며 공식 모델 제어 사양이나 성공 보장이 아니다.

2.5에서 격투·추격·메카·충격·등장 장면의 카메라를 고르거나, GODSTOUCH 연출을 요청하거나, 해당 장면을 실제 연속 원샷으로 바꿀 때 읽는다. 비액션 장면의 정적인 감정 연기에는 이 액션 구성을 기본 적용하지 않는다.

[아이캔디 연결](eyecandy-camera-direction.md)로 장면의 목적과 후보 적합성을 판단하고, 이 자료로 사건에 반응하는 카메라와 타이밍을 보강한 다음, [카메라 컴파일러](camera-motion.md)로 구체적인 촬영 문장을 만든다. 아래의 저자 용어를 새로운 EYECANDY 공식 카테고리로 등록하거나 부르지 않는다.

## 카메라가 움직이는 이유

먼저 장면에서 무엇이 바뀌는지 쓴다. 이어 그 변화를 보기 위한 카메라 반응을 정한다.

```text
인물의 행동·사건 → 카메라가 반응하는 이유 → 시작 구도
→ 주 이동·실제 경로 → 방향·속도·감속 → 인물 배치·초점
→ 읽혀야 할 순간 → 끝 구도·연속성
```

- 인물이 방향을 바꾸면 추적 경로가 따라 바뀐다. 새 대상이 보이거나 소리가 나면 그것을 확인하는 팬을 검토한다.
- 카메라를 실제로 흔드는 충격과, 관객의 주의를 옮기기 위한 연출 동기를 구분한다. “이유가 있는 카메라”가 모든 장면에서 부딪히거나 흔들려야 한다는 뜻은 아니다.
- 동작을 읽히게 하는 것이 목적이면 안정된 전신 구도나 고정 숏이 더 적합할 수 있다. 이미 지정된 고정·짐벌·참조 경로는 보존한다.
- 늦게 대상을 다시 잡거나 블러를 주는 연출은 선택 사항이다. 핵심 접촉·표정·제품 정보가 반드시 보여야 하는 순간을 가리지 않는다.

## 장면별 후보와 선택 조건

표는 상황에 맞는 후보를 찾는 출발점이다. 후보 여러 개를 한 비트에 모두 넣지 않는다.

| 장면 | 우선 검토할 촬영 | 구체화할 조건 |
| --- | --- | --- |
| 1 대 1 대결 | 측면 추적 또는 안정된 전신 투 숏 | 두 인물의 동작 방향·발 위치·접촉 지점이 읽히는 구도. 동작 축을 넘는다면 이동 경로를 명시 |
| 근접 접촉·잡기 | 가까운 인물의 어깨 너머 구도 | 실제 신체 접촉은 보존하면서 상대 얼굴·팔의 윤곽이 구별되는 시점. 억지로 접촉 자체를 없애지 않음 |
| 여러 인물이 있는 공간 | 한 경로를 따라가는 연속 추적 | 공간의 출입구·장애물·진행 방향을 먼저 정함. 새 대상으로 넘길 때 팬의 출발·도착 대상을 지정 |
| 추격 | 뒤따르기·측면 동행 | 인물과 카메라의 속도 관계, 회전·감속 지점, 장애물 통과 여유. 따라가기와 불필요한 주변 회전을 구분 |
| 결정적 충격·반응 | 읽히는 접촉 구도, 필요한 경우 짧은 속도 변화 | 접촉 순간과 반응을 보존. 접근이나 줌을 쓰면 방식과 복귀 경로를 명시 |
| 등장·새 정보 공개 | 실루엣 공개, 가림 해소, 필요시 높이 변화 | 무엇이 먼저 보이고 무엇이 나중에 보이는지 정함. 어둠·가림은 실제 장면에 있을 때만 사용 |
| 거대한 피사체 | 비교물이 포함된 넓은 구도, 필요시 아크·크레인 | 사람·차·건물 등 알려진 크기와의 관계로 규모를 설명. 비교물을 없는 참조에서 만들어냈다고 주장하지 않음 |
| 사건 이후 | 정지 또는 완만한 이동 | 남은 자세·소품·먼지·변형 상태를 관찰하고, 이미 생긴 결과가 다음 비트에서 초기화되지 않게 함 |

## 실제 원샷과 숨은 컷 구분

- **실제 원샷:** 시작부터 끝까지 한 카메라의 위치·높이·방향·렌즈·초점·속도 변화가 연결된다. 앞 비트의 끝 상태가 다음 비트의 시작 상태다.
- **Fake oner / stitched long-take:** 몸·어둠·블러 뒤에 편집을 숨겨 연속처럼 보이게 하는 방식이다. 원문에 함께 실려 있지만 실제 무편집 원샷과 동일하지 않다.
- 사용자가 원샷·원테이크·컷 없음을 요청하면 숨은 컷도 제외한다. 숨은 편집을 사용하려면 사용자가 그것을 허용한 작업이어야 한다.
- 휩팬은 같은 공간에서 출발 대상 → 회전 블러 → 도착 대상으로 연결한다. 블러를 다른 장소로 순간 이동하는 수단으로 쓰지 않는다.
- 갑작스러운 인서트·초근접·탑다운 전환은 원샷에 그대로 붙이지 않는다. 접근·회전·높이 변화에 필요한 시간과 통로가 있으면 하나의 경로로 풀고, 없으면 현재 시점에서 읽히는 구도로 단순화한다.
- 움직이며 끝내는 경우에도 마지막 인물 자세, 카메라 위치·이동 방향·속도·초점, 소품·빛·소리 상태를 기록한다. 원샷이 반드시 움직임 중간에 끝나야 하는 것은 아니다.

## 액션 타이밍

**준비 또는 숨 고르기 → 동작 → 접촉 → 즉각 반응 → 남는 결과**를 읽히게 배치한다. 모든 장면에 충돌을 새로 넣는 공식이 아니라, 이미 있는 사건의 인과 순서를 정리하는 틀이다.

- 접촉으로 생기는 충격·변형·소리는 접촉보다 앞서 발생하지 않게 한다. 접촉과 동시에 생기는 결과와 이후 퍼지는 먼지·파편을 구분한다. 모든 결과를 무조건 한 비트 늦추지 않는다.
- 짧은 감속을 쓰면 강조할 사건 하나와 원래 속도로 돌아올 지점을 정한다. 사용자나 원본 소스가 정한 리듬·립싱크를 임의로 늘이거나 줄이지 않는다.
- 액션에서는 짧은 하위 비트가 필요할 수 있다. 원문의 “30초 6–9비트”, “8초당 충격 최대 3회”는 복잡도를 줄이는 저자 휴리스틱이며 모델 한계가 아니다. 실제 요청 길이·동작 가독성에 맞춰 조정한다.
- 요청된 동작을 수치 예산 때문에 몰래 삭제하지 않는다. 겹치는 움직임을 순차화하고 부수적인 장식을 줄인다. 중요한 동작이 주어진 시간에 읽히기 어렵다면 그 충돌을 밝힌다.
- 이미 생긴 젖음·먼지·소품 위치·파손은 뒤 비트와 연장에 이어진다. 환상적 복구나 변신이 명시되면 해당 사건 이후의 새 상태를 사용한다.

## Lock 표기를 실제 문장으로 변환

`{camera=arc; radius=2m; cause=pivot_of_grapple; keep=outside_overlap;}`는 원문의 요약 표기다. 숨은 API나 실행 가능한 파라미터로 취급하지 않는다. 반경·각도·속도 숫자는 현재 UI나 경로 참조에서 제어되는 값이 아니라면 연출 의도로 취급한다.

변환 예시:

```text
주체: 두 인물이 팔을 맞잡은 상태에서 문 쪽으로 몸의 방향을 바꾼다.
카메라: 전신이 보이는 측면 투 숏에서 시작한다. 두 사람의 회전으로 상대 얼굴이 가려지는 것을 피하려고, 문 앞의 열린 통로를 따라 짧고 완만한 아크로 동행한다. 인물의 회전 속도에 맞추고 근접 인물의 어깨 너머로 상대 얼굴과 잡힌 팔이 구별되는 구도로 끝낸다. 초점은 두 사람의 접촉을 읽을 수 있는 범위에 두고, 광학 줌과 컷 없이 직전 위치에서 이어진다.
```

`locked-off + drift`, `고정 + push`처럼 같은 제어 항목이 충돌하면 실제 원하는 방식을 선택한다. 본체 전진, 조준 회전, 초점 이동을 별도 절로 작성하면 함께 가능한 움직임도 구별할 수 있다.

## 다른 2.5 규칙과의 우선순위

요청된 길이·컷 정책·카메라·참조·음향·결말을 우선한다. 원문의 21:9, 24fps/180도 셔터, 차가운 금속광, 핸드헬드, 히어로샷 금지, NO BGM, 움직임 중간 종료는 이 자료의 스타일 선택이다. 사용자가 선택한 항목만 적용하며 일반 장면의 기본값으로 확장하지 않는다.

음향은 [NO-BGM 가이드](no-bgm.md)의 현장음·완전 무음·소스 전용·무반주 보컬 구분을 따른다. 완전 무음에 접촉음·발소리를 추가하지 않고, 요청한 음악을 GODSTOUCH의 음악 금지 문구로 삭제하지 않는다.

최종 출력은 기본 2.5 스킬의 완전한 프롬프트 하나와 정확한 길이 보고, 필요한 참조 역할 맵, 짧은 카메라 근거를 따른다. 내부 선택표나 lock manifest를 별도 프롬프트로 덧붙이지 않는다. 수정에서는 바뀐 사건에 의존하는 카메라·타이밍만 다시 설계하고 영향을 받지 않은 값을 유지한다.
