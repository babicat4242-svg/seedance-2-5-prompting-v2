# 영상 효과 연출 · Video Effects

아이캔디의 촬영·편집 기법과 힉스필드의 시각 효과를 함께 다루는 공통 진입점이다. 사용자에게는 ‘영상 효과 연출’로 안내하고 출처는 자료 안에서 구분한다. 효과를 영화·브랜드필름·광고·뮤직비디오에 쓸 수 있는 장면 언어로 설계한다. Higgsfield Effects는 시각적 발상의 참고 자료이며, 결과물은 어떤 영상 도구에도 전달할 수 있는 완전한 연출·프롬프트다. 기본 작업에는 계정·API·플러그인·실시간 카탈로그 조회가 필요하지 않다.

## 분석 기반 완성형 프롬프트

바로 적용할 예시가 필요하면 [완성형 프롬프트 모음](references/prompt-library/index.md)에서 관련 효과를 읽는다. 아이캔디 132개와 힉스필드 81개, 총 213개 출처 예시에 원본 미디어·관찰 프레임·분석·뮤직비디오와 브랜드필름용 완성 프롬프트 426개가 있다. 212개는 시간순 표본 프레임, Dreamcore 1개는 정지 원본을 확인했다. 고유 효과 종류 213개나 실제 생성 성공 426건이라는 뜻은 아니다. 장면에 맞게 다시 작성하며 사용자 길이·컷·참조·음향 조건을 보존한다.

## 공통 기법 자료

카메라·구도·조명·전환 또는 아이캔디의 움직이는 예시를 적용할 때는 [기법과 움직이는 예시 적용](references/visual-techniques.md)을 읽는다. 기존 아이캔디 색인·상세 파일을 이 라이브러리의 자료로 사용한다. 이름과 설명을 연결한 것과 각 애니메이션을 실제 분석한 것은 구분한다.

## 장면부터 선택

사용자의 장면, 보여줄 대상, 끝에 남길 감정·정보, 길이, 컷 정책을 먼저 파악한다. 주어진 내용으로 초안을 만들 수 있으면 진행한다. 도구가 정해지지 않았으면 범용 자연어로 작성한다.

- **영화:** 효과가 인물의 인식·갈등·선택이나 사건의 결과에 어떤 변화를 주는지 정한다.
- **광고:** 효과가 제품의 형태·재질·기능·브랜드 감각 중 무엇을 보여주는지 정한다.
- **뮤직비디오:** 효과를 퍼포먼스·구절·음악의 변화·시각적 반복과 연결한다.
- 같은 효과를 세 용도 모두에 적용할 수 있다. 효과별 장르를 고정하거나 영화 요청을 자동으로 바이럴 광고로 바꾸지 않는다.
- 요청된 복합 효과는 보존하되 각각의 대상·순서·관계를 정한다. 단순한 장면에 이펙트를 의무적으로 추가하지 않는다.

용도별 설계가 필요하면 [영화·광고·뮤직비디오 적용](references/genre-direction.md)을 읽는다. 효과 선택·재구성에는 [효과 라이브러리](references/effect-selection.md)에서 관련 항목만 읽는다.

효과 색인은 핵심 14개·추가 장면 34개·화면 스타일 33개로 구성된다. 그림·명화를 실제 인물로 재현하는 유형은 사용자 요청으로 제외하며 추천하지 않는다. 잉크·종이·색감 등 화면 질감은 유지한다. 스타일의 시간 변화는 새 각색이며 필수가 아니다.

Monster dab은 사람 1장·몬스터 1장의 독립 참조를 기본으로, Scrapbook collage는 인물 외에 배경·원하는 소품의 이미지 또는 설명도 받을 수 있도록 설계한다. 실제 태그별 역할을 보존하며 원본 서비스의 슬롯 수를 범용 연출에 상속하지 않는다. 자세한 구성은 [추가 장면 카드](references/effects-scenes.md)에서 선택한다.

## 장면에 맞는 아이디어

촬영·구도·조명·광학·시간·질감·복제·합성·물성·공간 변형·전환 모두에 [장면별 아이디어 설계](references/visual-techniques.md)를 적용한다. 원본에서 실제 확인한 작동 원리를 장면의 감정·행동·제품·브랜드 톤·퍼포먼스에 맞춰 재설계한다. 원본 소재를 자동으로 복사하거나 모든 효과를 장면 전환으로 만들지 않는다. 사용자가 동일 재현을 명시하면 그 요청을 따른다. 저장된 완성 프롬프트는 각색 예시이며 실제 장면에 맞춰 다시 작성한다.

## 효과와 카메라의 공동 연출

장면·아이디어·완성 프롬프트에는 [연출과 움직임 설계](references/directing-choreography.md)를 적용한다. 관객의 시선, 발동 계기, 주체·카메라·효과의 타이밍, 속도 변화, 도착 구도를 함께 설계한다. Eyes in에서는 사용자 선호인 회전하며 눈으로 접근하는 안을 장면에 맞게 검토한다. 회전+접근 등 역할이 다른 복합 동작을 기계적으로 삭제하지 않고 각각의 축·대상·속도·끝을 정의한다.

## 효과를 여섯 요소로 풀기

`시작 상태 → 발동 계기 → 변형 대상·과정 → 카메라 → 도달 상태 → 다음 장면 연결`

각 요소를 관찰 가능한 문장으로 쓴다. 무엇이 움직이고 무엇이 유지되는지, 공간·시간·물성 중 무엇이 바뀌는지 명확히 한다. 의도한 변형까지 일관성 규칙으로 금지하지 않는다.

효과 이름만 적고 모델이 내부 프리셋을 알아서 실행한다고 가정하지 않는다. 예를 들어 Cutout은 배경의 분리·층별 움직임·빈 공간·복귀를, Bullet time은 멈춘 대상과 계속 움직이는 카메라를 모두 설명해야 한다. 카메라 이동, 피사체 동작, VFX, 편집, 재생 속도, 오디오는 별도 축이다.

원본 영상이 있으면 실제 확인한 움직임을 분해한다. 이름과 공개 설명만 있으면 그 근거로 작성한 각색임을 구분한다. 라이브러리에 없는 공식 효과의 동작이 불분명할 때는 공개 상세나 제공 자료를 확인한다. 자료가 없으면 설명된 시각 의도로 초안을 만들고, 이름만 있어 핵심 동작을 알 수 없을 때만 필요한 설명을 요청한다.

## 결과물

요청 범위에 맞춰 작성한다. “프롬프트만”이면 완전한 복사용 프롬프트만 제공한다. 모델별 출력 계약이 활성화돼 있으면 그 계약을 우선한다.

- **추천:** 효과의 시각적 원리, 이 장면에서의 역할, 짧은 적용안을 제시한다. 수량은 사용자 요청을 따른다.
- **장면·콘티:** 연출 의도 → 시작/변화/끝의 행동 → 별도 카메라·편집·음향 계획 → 다음 숏과의 연결.
- **프롬프트:** 대상·공간·행동·효과 전체 과정·카메라·마지막 상태를 한 번에 붙여넣을 수 있게 작성한다. 실제 참고 이미지가 없으면 보았다고 쓰거나 태그를 만들지 않는다.
- **모델별 변환:** 같은 장면을 유지하며 해당 모델의 확인된 참조 문법과 길이·출력 형식으로 바꾼다.

요청 언어를 따르고, 미지정이면 대화 언어로 작성한다. 시간 미지정 초안은 시작/중간/마지막으로 설명할 수 있다. 사용자가 요청한 길이·음원·원테이크를 보존한다. 단일 숏 요청을 임의로 멀티컷으로 바꾸지 않는다.

## 도구에 옮기기

모델이 지정됐거나 실제 제작 방식이 필요하면 [모델 적용과 제작](references/execution.md)을 읽는다. Seedance 2.5, Kling, Runway, Veo 등은 대상 도구의 예이며 동등한 기능 지원을 뜻하지 않는다. 이미 해당 모델 스킬을 사용 중이면 그 규칙을 유지하고 이 스킬에서는 효과 내용만 가져온다.

Higgsfield의 필수 슬롯, 프리셋 ID, 크레딧·해상도·기본 길이를 다른 도구로 옮기지 않는다. “공중 정지한 향수병”에는 인물 이미지가 필요하지 않다. 사용자가 원할 때 인물의 낙하를 제거한 제품 중심 변주로 설계한다.

프롬프트 작성은 영상 생성 요청과 구분한다. 실제 생성은 사용자가 고른 도구와 기존 실행 의사에 따라 처리한다. 다른 도구에 맞춘 프롬프트를 작성했다는 사실과 실제 생성·재현에 성공했다는 사실을 구분한다.

## 사용 예

- `$video-effects 이 장면을 영화 속 기억 붕괴 장면으로 연출해 줘.`
- `$video-effects 향수병 공중 정지를 광고 프롬프트로 써줘. 인물 없이.`
- `$video-effects Cutout을 뮤직비디오 후렴에 쓰고 싶어. 씨댄스 2.5로 작성해 줘.`
